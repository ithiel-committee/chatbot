# 展示運用・安全配布マニュアル (iThiel Chatbot)

本ドキュメントは、展示会・学園祭・イベント等の短期運用 (準備1日 + 展示2日 など) において、**レンタルPCや他人のノートPCで安全かつ手軽にアプリを動かすための配布・運用手順書** です。

---

## 1. 基本方針 (結論)

- **配布手段**: Google ドライブではなく **「USBメモリ」** を使用する
- **APIキー管理**: 普段のキーではなく **「展示専用の使い捨てキー」** を新規発行し、**展示終了後に即時削除** する
- **キーの渡し方**: exe の中に埋め込まず、**exe と同じフォルダに `.env` を置いて USB で持ち込む**

---

## 2. 配布・ファイル構成

### なぜドライブ共有ではなく USBメモリなのか？

1. **流出リスクの遮断**: ドライブの共有設定ミスや、クラウド上に課金キー入りファイルが残り続ける事故を防ぐ。
2. **設営スピード・確実性**: 会場や準備室の Wi-Fi 環境が不安定・低速でも、数百MB の exe を瞬時に PC へ展開できる。
3. **撤収の手軽さ**: 終了後は PC 上のフォルダを完全削除 (Shift + Delete) するだけでクリーンアップ完了。

### USBメモリ内のフォルダ構成

USBメモリ内に下記のようなフォルダを作成して持ち込みます。

```text
USBメモリ/
  └── iThiel-Chatbot/                    # 解凍済みフォルダ (win-unpacked を丸ごとコピー)
        ├── iThiel-Chatbot.exe           # ★実行ファイル本体 (解凍不要・3〜5秒で即起動！)
        ├── .env                         # 展示専用のAPIキー等を記述した設定ファイル
        ├── logs/                        # 会話ログフォルダ (起動・会話時に自動生成・永続保存)
        │     └── log_YYYY-MM-DDTHH-mm-ss.json
        ├── resources/                   # Next.js / Electron 実行用リソース
        └── ... (各種 dll / pak ファイル)
```

> **【重要】起動速度についての注意**:
> 単一の `iThiel-Chatbot-Portable.exe` は起動するたびに Windows の一時フォルダへ巨大な内部ファイル（1GB以上）を自己解凍するため、起動に数分〜10分近くかかります。
> 展示現場では、事前に解凍された上記フォルダ一式を持ち込み、中の **`iThiel-Chatbot.exe`** を起動してください。自己解凍待ちがなく **3〜5秒で即座にアプリが立ち上がります**。
>
> **Note**: アプリ (`electron.mjs`) は、exe と同じフォルダに `.env` が存在する場合、それを最優先で自動ロードする仕様になっています。そのため、相手のPCで設定画面を開いてキーを入力する手間はありません。
> また、来場者との会話ログは exe と同じ階層の `logs/` フォルダへ自動保存されます。アプリ終了後も USBメモリ内にログが保持されるため、展示終了後の会話分析に活用できます。

#### 同梱する `.env` の記述例

```env
# 展示専用に発行した Gemini API キー
GEMINI_API_KEY="AIzaSy..."

# 音声認識方式 (Electronデスクトップ推奨の gemini)
NEXT_PUBLIC_SPEECH_RECOGNITION_MODE="gemini"

# （必要に応じて他の設定項目）
```

## 3. 課金 API キーを守る「3重の安全策」

レンタルPCや他人のPCに課金キーを渡すことになるため、以下の3ステップで金銭被害を完全に防ぎます。

### ① 展示専用キー (使い捨てキー) の発行

普段の開発・個人利用キーは絶対に使わず、Google AI Studio (または Google Cloud Console) で展示専用のキーを1つ新規発行します。

- **キーの名前例**: `iThiel-Exhibition-2026`
- **制限設定**: APIの制限で「Generative Language API (Gemini)」のみを許可

### ② 予算アラート・クォータ (利用上限) の設定

Google Cloud Console 側で以下の安全装置をかけておきます。

- **予算アラート**: 例えば「1,000円」「2,000円」に達した際にメール通知
- **1日のリクエスト上限**: 万が一の連続入力や暴走を防ぐため、1日あたりの最大リクエスト数を設定

### ③ 【最重要】展示終了後の即時キー削除 (Revoke)

展示が終わった瞬間に、手元のスマホや自分のPCから Google AI Studio にアクセスし、**該当の展示用キーを「Delete (削除)」** します。

- **効果**: キーを削除した瞬間にそのキーは無効化されます。相手のPCや USBメモリに `.env` のコピーが残っていても、第三者が利用することは永久に不可能になります。

## 4. イベント運行タイムライン

| フェーズ         | タイミング     | 作業内容                                                                                                                                                                                                 |
| :--------------- | :------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **事前準備**     | 展示2〜3日前   | 1. `pnpm run build:exe:portable` で最新の Portable.exe を生成<br>2. Google AI Studio で展示専用の `GEMINI_API_KEY` を新規発行<br>3. USBメモリに `iThiel-Chatbot/` フォルダを作成し、exe と `.env` を配置 |
| **設営・準備日** | 準備日 (1日目) | 1. 現地PCのデスクトップ等に USB から `iThiel-Chatbot/` を丸ごとコピー<br>2. exe を起動し、マイクボタンを押して音声認識・会話ができるかテスト<br>3. ディスプレイ解像度や音量バランスを調整                |
| **展示本番**     | 本番 (2日間)   | そのままブースで運用 (必要に応じてキオスクモードやフルスクリーン表示)                                                                                                                                    |
| **撤収・完了**   | 展示終了直後   | 1. 現地PC上の `iThiel-Chatbot/` フォルダを完全に削除 (Shift + Delete)<br>2. **自分のスマホやPCから Google AI Studio を開き、展示用キーを削除**                                                           |

## 5. トラブルシューティング

- **マイクを押しても反応しない / すぐ切れる**:
  - Windows の「設定」→「プライバシーとセキュリティ」→「マイク」で、アプリへのマイクアクセスが許可されているか確認する。
  - アプリの設定画面（歯車アイコン）→「音声入力」で、音声認識モードが「Google Gemini」になっているか確認する。
- **音声が出ない**:
  - Windows の既定のオーディオ出力デバイス（スピーカー / モニター）が正しく選択されているか確認する。
  - 音声合成（VOICEVOX / AivisSpeech 等）を使用する場合は、該当の音声エンジンがバックグラウンドで起動しているか確認する（クラウド音声の場合は不要）。

## 6. 万が一のフォールバック (exeが動かない場合のソース実行手順)

セキュリティソフト等の干渉により、現地PCでポータブル exe がどうしても起動しない場合に備えた、ソースコードからの直接起動手順です。

### 事前準備 (USBメモリに入れておく推奨バックアップ)

会場のWi-Fiは低速・不安定なことが多いため、**巨大なパッケージのダウンロードを現地で行わない構成** が最も安全です。

```text
USBメモリ/
├── 1_Node_Installer/
│     └── node-v22-x64.msi        # Node.js 公式LTSインストーラー (オフライン用)
├── 2_Chatbot_Source/             # プロジェクト一式 (事前に pnpm install 済みの node_modules 込み)
│     ├── .env                    # 展示用APIキー
│     ├── package.json
│     ├── node_modules/           # 事前に手元でインストールしたものをそのまま同梱
│     └── ...
└── 3_Portable_EXE/
      ├── iThiel-Chatbot-Portable.exe
      └── .env
```

### パターンA: USBから丸ごとコピーして動かす場合 (最速・ネット不要)

1. **Node.js のインストール**:
   - USB内の `node-v22-x64.msi` を実行し、標準設定のままインストールを完了する。
2. **フォルダの配置**:
   - `2_Chatbot_Source` フォルダを現地PCのデスクトップ等へコピーする。
3. **PowerShell の起動**:
   - コピーしたフォルダを開き、エクスプローラーのアドレスバーに `powershell` と入力して Enter を押す。
4. **開発サーバー起動**:
   ```powershell
   npm run dev
   ```
   (または `node scripts/dev-server.js`)
5. **ブラウザで利用**:
   - ブラウザで `http://localhost:3000` を開く。`F11` キーで全画面表示に切り替え可能。

### パターンB: 現地PCで真水から clone して動かす場合 (完全手動フロー)

USBにソース一式を事前同梱しておらず、GitHub から新しく落とす場合の手順です。

1. **Node.js & Git のインストール**:
   - 公式サイトから [Node.js (LTS)](https://nodejs.org/) および [Git for Windows](https://git-scm.com/) をダウンロードしてインストールする。
2. **PowerShell のスクリプト実行制限を一時解除**:
   - PowerShell を開き、スクリプト実行ポリシーをセッション限定で許可する:
     ```powershell
     Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
     ```
3. **リポジトリのクローン**:
   ```powershell
   git clone https://github.com/ithiel-committee/chatbot.git
   cd chatbot
   ```
4. **.env の配置**:
   - クローンした `chatbot` フォルダの直下に、USBメモリの `.env` を貼り付ける。
5. **pnpm の有効化と依存関係インストール**:
   ```powershell
   corepack enable
   pnpm install
   ```
6. **開発サーバーの起動**:
   ```powershell
   pnpm dev
   ```
7. **動作確認**:
   - `http://localhost:3000` にアクセスし、会話ができるか確認する。
